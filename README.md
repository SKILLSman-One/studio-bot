# Studio Bot — один бот для моделей и администратора

Бот работает на Windows обычным Python. Для будущего Linux-сервера также подготовлена сборка Docker; для локального запуска Docker не нужен. Один процесс и один Telegram-бот: `/start` открывает меню, `/admin` — вход администратора по паролю. `/model` или `/logout` закрывает админ-сессию и возвращает кабинет модели.

**Первый запуск версии 0.7.2:** откройте [START-HERE.md](START-HERE.md). Нужен Python **3.11+**, без требования конкретно 3.13. `Verify.cmd` проверяет комплект, `Install.cmd` выбирает установленный Python, создаёт окружение и шаблон `.env`. Рабочие секреты передаются отдельно. Для Linux доступны обычный Python и необязательный Docker. Сам ZIP не содержит настроенной учётной записи.

При клонировании из GitHub начинайте с `Install.cmd` или `python3 bootstrap.py install`: `Verify.cmd` предназначен для готового ZIP-выпуска с `MANIFEST.sha256`. В репозитории нет рабочего токена, Google-ключа и базы; скопируйте их из отдельного комплекта хостинга либо выполните новую настройку по START-HERE.md.

На хостинге с полем «Главный файл» (например Bothost) укажите **`main.py`**: он запускает пакет с командой `run`. `package_release.py` собирает архив, а запуск папки `studio_bot` как файла нарушает относительные импорты. Ключ Google и база размещаются в постоянной папке `data`; токен и `ADMIN_PASSWORD_HASH` задаются в переменных окружения хостинга. Собственный Dockerfile — отдельный вариант запуска.

Настроены комнаты **4–15** и время **Санкт-Петербурга (Europe/Moscow)**. Сервер пока не выбран; сборка подготовлена к размещению, но в интернете не запущена.

**Статус зарплатной интеграции:** подключены таблицы «Учет Сентябрь» и «Учет Октябрь», вкладки «Чеки». Модель видит свой заработок в USD с учётом её процента; администратор — полную выручку действующего состава. Поддерживается несколько месячных файлов; каждый читается заново при запросе отчёта. Google-таблица не изменяется. На сервере ключ нужно отдельно разместить в `secrets/google-service-account.json`.

## Действующий состав

Список для зарплатной привязки и общая сводка оборота (включая CSV) используют только сотрудников из самой новой подключённой месячной таблицы — сейчас из октября 2026. Сентябрьские имена не добавляются к действующему составу. При подтверждении привязки состав проверяется заново. Сентябрьские начисления действующих сотрудников доступны для октябрьских выплат; история бывших не удаляется, но в сводку действующего состава не включается. Старые Telegram-анкеты и блокировки сохраняются отдельно.

## Что работает в приложении

| Модели | Администратор |
|---|---|
| Регистрация сотрудника: только рабочее имя/псевдоним; повторная подача после отказа | Подтверждение доступа сотрудника и привязка к таблице; пересмотр отказа |
| Свободные и занятые комнаты | Кто сейчас на смене, в какой комнате и с какого времени |
| Начало и завершение своей смены | Принудительное завершение смены с уведомлением модели |
| Запись в четверг–пятницу: день следующей недели, своё время, комната | Разбор пересечений: другая комната, изменение времени или отказ |
| Свои предстоящие записи и отмена | Общее подтверждённое расписание |
| Свой заработок за выбранные даты в USD | Полный оборот всех моделей за период в USD |
| Заявка на аванс со снимком текущего и прошлого периода | Одобрение/отказ по авансу и отдельная отметка фактической выплаты |
| Сообщение администратору | Ответ модели через бот и журнал доставки уведомлений |
| Доступ к своему кабинету после одобрения | Бан и разбан; продолжительность использования комнат |

Начисления и авансы станут доступны после выдачи серверу доступа к Google-таблице и привязки модели. Подтвердить анкету для комнат, смен и расписания можно независимо от зарплатной таблицы.

Бот предназначен для действующих сотрудников студии. При первом входе достаточно указать рабочее имя или псевдоним, как в таблице: запрос сразу отправляется на подтверждение администратору. Вопросов про опыт и комментариев при регистрации нет.

## Правила работы

- Занятость комнаты начинается, когда модель нажимает «Начать смену». Одна модель может иметь одну активную смену, одна комната — одного человека. При завершении сохраняется длительность. Если забыли завершить смену, её закрывает администратор. Бот не определяет физическое присутствие автоматически.
- После перезапуска незавершённая смена продолжает отображаться занятой: история не сбрасывается. Статистика за период учитывает только пересечение времени смены с этим периодом.
- Следующая неделя — понедельник–воскресенье по времени студии. Фиксированных слотов в меню нет: сотрудник указывает начало и конец. Сохранённые заявки содержат собственные даты и время.
- Свободное посещение: сотрудник может начать смену без предварительной записи в любой день, если комната свободна. После нажатия «Начать смену — 4-я комната» приходит отдельное уведомление «Твоя смена началась». Автоматического определения прихода по геолокации нет.
- Предварительная запись открыта с четверга 00:00 до пятницы 23:59:59 по Санкт-Петербургу, на следующий понедельник–воскресенье. Сотрудник выбирает день, пишет интервал `14:00–19:30`, выбирает комнату и подтверждает. Ночное посещение `23:00–02:00` заканчивается на следующий день; обе даты показаны перед подтверждением.
- Свободная комната бронируется сразу. При пересечении создаётся запрос «на разборе», который не занимает комнату; администратор получает уведомление и видит его в «Записи на разбор». Можно выбрать другую комнату, изменить время в пределах выбранного дня или отклонить запрос. Двойная бронь запрещена, соседние интервалы допустимы. Доступность перепроверяется в транзакции при подтверждении, а окно записи — на каждом шаге. Незавершённое подтверждение действует 5 минут.
- Бронь сама не запускает и не завершает смену. Текущая бронь мешает другой модели начать смену в этой комнате; затянувшуюся смену администратор завершает вручную.
- Модель видит только свои начисления. Зарплатную строку связывает администратор: в карточке сотрудника нажимает «Связать с таблицей», выбирает имя из списка и подтверждает. Ввод внутренних ID не требуется. Список показывает свободные записи, по 8 на страницу; совпадающие псевдонимы нужно сначала различить в таблице. Перед сохранением бот повторно читает таблицу и проверяет доступность привязки. Один ID нельзя связать с двумя Telegram-пользователями. Перестановка строк, регистр и лишние пробелы не меняют ID. Смена самого псевдонима создаёт другой ID: перед таким изменением нужно перенести привязку и исторические имена согласованно; автоматического объединения разных псевдонимов нет.
- После отклонения анкеты модель может открыть `/start`, подать анкету заново или написать администратору. Администратор может подтвердить отклонённую анкету из её карточки без повторной подачи. Повторная подача сохраняет историю обращений и не создаёт второго пользователя.
- Модель видит **свой заработок в USD с учётом её процента** из листа «Модели»; индивидуальный процент имеет приоритет. Администратор видит полный оборот всех моделей. Новая заявка на аванс содержит заработок модели за текущий и прошлый периоды. В сообщениях остаются только период, имя и суммы: пояснения о проценте, источнике и времени чтения не выводятся.
- Для аванса и кнопок зарплаты настроены периоды **1–15 и 16–конец месяца**, как в формулах «Чеки». Текущий период считается по сегодня, предыдущий берётся целиком. Для просмотра можно задать произвольные даты. `payroll_period = "monthly"` возвращает календарные месяцы.
- Новые заявки на аванс принимаются только в USD (например `100 USD`) и содержат снимок заработка за два периода. Время чтения сохраняется внутри заявки для истории, но не показывается в сообщении. Предпросмотр действует 5 минут. Повторное подтверждение не создаёт дубликат. До обработки или отметки выплаты новой открытой заявки той же модели не будет.
- «Одобрить аванс» не переводит деньги. «Отметить выплату» — запись администратора о состоявшейся выплате. Бот не меняет Google-таблицу. В отчёте по дате выплаты одобренные авансы вычтены из суммы к получению; отчёт о заработке за произвольные даты показывает сами начисления.
- Сводка оборота помещается в одно сообщение. Если полный список превышает ограничение Telegram, приходит одно сообщение с CSV-файлом полной сводки `oborot.csv`. Длинные расписания и журналы приходят одним текстовым файлом.

## Бан и разбан

В главном меню `/admin` есть отдельные кнопки **«Заблокировать»** и **«Разблокировать»**. Выберите сотрудника из соответствующего списка и подтвердите действие. Списки показываются по 8 человек, собственный аккаунт исключён. Эти кнопки также остаются в карточках моделей.

- Бан закрывает все команды и старые кнопки, включая вход в админку. Самого себя заблокировать нельзя.
- Активная смена завершается с сохранением длительности, ещё не завершившиеся записи отменяются. История, зарплатная привязка и авансы сохраняются; администратор может обработать прежние финансовые заявки.
- Уведомления заблокированному пользователю отменяются. Уже переданные Telegram сообщения отозвать таким баном нельзя.
- Разбан возвращает прежний статус анкеты и привязку. Отменённые записи и завершённые смены не восстанавливаются. Отклонённая анкета после разбана снова допускает повторную подачу.
- Блокировка хранится в SQLite и сохраняется при перезапуске. Она относится к Telegram ID; доступ с новым аккаунтом требует отдельного одобрения анкеты.

## Состояние бота

Кнопка «Состояние бота» в главном меню администратора показывает версию работающего экземпляра, время запуска, доступность SQLite и результат свежего чтения Google. Указаны последнее успешное чтение и месяцы последнего успешного снимка; при ошибке они не выдаются за свежие данные. «Проверить снова» повторяет запрос. Время — Санкт-Петербург. Суммы зарплат и секреты в диагностике не отображаются; модели этот раздел недоступен.

## Очистка тестовой истории

При согласованном разовом сбросе перед первым запуском 0.6.0 создаётся проверенная копия базы в `backups`. Удаляются сотрудники и привязки, блокировки, смены, слоты, авансы, обращения, очередь уведомлений и журнал действий. Настройки, токен, пароль администратора и Google-ключ сохраняются. После сброса администратор входит заново, сотрудники повторно регистрируются. Кнопки сброса в Telegram нет; обычный запуск ничего не очищает.

Старые сообщения в Telegram остаются, но их кнопки не работают после сброса. Откройте `/start` или `/admin`: каждая новая кнопка содержит идентификатор поколения базы. Он сохраняется между обычными перезапусками и меняется при сбросе. Кнопки версий до 0.6.0 также потребуют открыть меню заново. Резервные копии не входят в Git, Docker-образ и архив исходников.

## Обновление до 0.7.1

Остановите прежний процесс бота и сохраните копию папки `data`. Обновите исходники, сохранив рабочие `.env`, `data` и ключ Google. При старте база автоматически получит недостающие поля и служебное состояние кнопок; существующие записи не удаляются. Затем запустите `Start.cmd` (для сервера — пересоберите Docker-образ) и отправьте `/start`. Не запускайте две копии бота одновременно.

## Чистота перед завершением смены

Сотрудник нажимает «Завершить мою смену». Для комнат **4, 8, 9, 10, 12, 13, 14** бот отправляет по две эталонные фотографии и спрашивает «У тебя так же чисто?». Единственная кнопка — «✅ Да, всё чисто». Она завершает смену и сохраняет время подтверждения в истории. Отправлять фото или текст в ответ не нужно. Пока сотрудник убирает, смена продолжает идти. Подтверждение действует 30 минут; после перезапуска нужно открыть завершение снова.

Фотографии находятся в `assets/rooms`, соответствие задаётся секцией `[room_photos]` в `studio.toml`. Они включены в Docker и архив. Для комнат без фотографий показывается текстовый вопрос о чистоте с той же кнопкой. При ошибке загрузки настроенных фотографий смена остаётся открытой. Администратор может завершить её принудительно; такая операция не записывается как подтверждение чистоты сотрудником. Это подтверждение самим сотрудником, а не автоматическая проверка изображения.

## Даты выплат и авансы

- 5 октября — заработок за 1–15 сентября; 20 октября — за 16–30 сентября. В ноябре выплачивается октябрь, в январе — декабрь предыдущего года. 15-е число считается только в первой половине. Длина месяца и високосный февраль учитываются автоматически.
- В «Мой доход» есть ближайшая и предыдущая даты выплат, текущий/прошлый период заработка и произвольные даты. Заработок — начисления с долей модели. Отчёт по дате выплаты дополнительно показывает авансы и сумму к получению. Администраторский оборот остаётся полным, без вычета авансов.
- При **одобрении** нового аванса сумма в USD закрепляется за ближайшей датой выплаты по времени Петербурга и сразу вычитается из неё. В сам день 5-го/20-го аванс относится к этому дню до 23:59:59. Повторное одобрение запрещено. Отметка «выплачен» не переносит вычет и не вычитает второй раз. Отклонённая или ожидающая заявка ничего не вычитает.
- Если авансов больше начисления, бот показывает отрицательный остаток и предлагает уточнить расчёт у администратора. Автоматического переноса долга, перевода денег или изменения Google Sheets нет. Авансы, одобренные до версии 0.7.0, не распределяются по датам задним числом; их прежняя история сохранена.
- Сентябрьская таблица включает 1 октября в формулы общих итогов. Для неё задано `totals_include_next_month_day = true`: дополнительный день участвует только в сверке формул, а в сентябрьский заработок не попадает. Октябрь читается из своего файла.
- `inactive_names` в источнике содержит подтверждённых бывших сотрудников. Они скрыты при новой привязке; историческая выручка сохраняется в исходных данных. Без исторического процента их личный заработок недоступен, но расчёт других моделей работает.

### Новый месячный файл

Предоставьте сервисному аккаунту доступ читателя к новому файлу. Добавьте отдельный `[[payroll_sources]]` в `studio.toml` с `format = "studio_daily_share"`, `calculation_confirmed = true`, ID файла, `month = "2026-11"`, диапазонами «Чеки» и «Модели». Старые источники сохраняйте. Не копируйте сентябрьский флаг дополнительного дня без проверки формул нового файла. Выполните `CheckGoogle.cmd`, затем перезапустите бот (на сервере — `docker compose up -d --force-recreate`). Новые файлы подключаются явно; содержимое подключённых таблиц обновляется автоматически.

## Обновление зарплат

Сервер читает Google Sheets API с правом **только чтения**. Фоновое обновление выполняется раз в 60 секунд после завершения предыдущего чтения; кнопка зарплаты и «Обновить» запрашивают данные сразу. Это обновляемая сводка, а не непрерывный поток: задержка Google, сети или пересчёта формул влияет на свежесть. Пока таблица не обновлена её владельцем, новых начислений в боте тоже не будет.

При ошибке доступа, неверных значениях или повторяющихся ID начислений расчёт останавливается с понятным сообщением. Старые зарплаты не подставляются вместо свежих. Смены, комнаты и расписание продолжают работать.

Курс валют полностью удалён: кнопок, запросов к ЦБ и пересчётов в рубли нет. Старые кнопки курса открывают меню. Исторические авансы сохраняют исходную сумму и валюту заявки; сохранённые курсы и рублёвые пересчёты больше не отображаются. Старые долларовые снимки с долей модели не подменяются полным оборотом задним числом.

## Подготовка доступа

1. Нужен **один бот** и один `BOT_TOKEN` от [@BotFather](https://t.me/BotFather). В рабочей локальной папке предоставленный токен уже сохранён и проверен через Telegram; в архив секреты не включаются.
2. Для входа в админку достаточно пароля: `/admin` в личном чате. `ADMIN_IDS` по умолчанию пустой. Если позже заполнить его числовыми Telegram ID через запятую, вход дополнительно ограничится этим списком. Уведомления о новых заявках начнут приходить после первого успешного входа; существующие заявки уже видны в разделах админки.
3. Для серверного чтения Google-таблицы создайте сервисный аккаунт Google Cloud и включите Google Sheets API. Предоставьте его `client_email` доступ **читателя** к конкретной зарплатной таблице. Авторизация через подключение Google Drive в чате нужна для изучения структуры, но сама по себе не авторизует отдельный сервер.
4. Сохраните ключ сервисного аккаунта на сервере в `secrets/google-service-account.json`. Для Windows — `data/google-service-account.json`, либо задайте `GOOGLE_APPLICATION_CREDENTIALS`.
5. Октябрьский источник уже заполнен в `studio.toml`. После выдачи доступа запустите `CheckGoogle.cmd` на Windows либо `docker compose run --rm studio check-google` на сервере. Команда читает реальные диапазоны, проверяет структуру и выводит количество моделей и доступные месяцы без зарплатных сумм. Токен Telegram для этой проверки не требуется. Если настройку ещё не выполняли, для Docker скопируйте `.env.example` в `.env`; `setup` заполнит такой шаблон, сохранив уже введённый токен.

Подробности API: [чтение значений Google Sheets](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get), [право spreadsheets.readonly](https://developers.google.com/workspace/sheets/api/scopes).

### Подключённый формат «Чеки»

В `studio.toml` включён `format = "studio_daily_share"`, месяц `2026-10`. Читаются вычисленные значения из `Чеки!H1:AR` и `Модели!G1:J` одним запросом [Google Sheets batchGet](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchGet). Диапазоны охватывают добавленные строки. Даты N1:AR1 должны соответствовать месяцу в конфигурации.

- H — псевдоним в итоговой строке модели; N:AR — дневная выручка. Строки отдельных площадок повторно не суммируются. Служебные строки «Работающие модели» пропускаются только при нулевых суммах.
- G:H листа «Модели» — основной процент, I:J — индивидуальный. Парсер проверяет эту структуру. Кабинет модели и новые авансы используют выручку × процент модели. Полный оборот администратора не зависит от процента. Изменение процента пересчитывает заработок за все дни соответствующего месяца.
- Дневные итоги суммируются без промежуточного округления, в ответе — два знака. Удержания, долги и выданные авансы автоматически не вычитаются. Полная сумма из «Чеки» обозначена как оборот.
- Дневные значения сверяются с J:L каждой модели, затем сумма моделей — с общей строкой «Сумма за день». Расхождения больше одного цента, пропущенные итоговые строки или неверные даты дают ошибку вместо частичного отчёта.
- Подключены сентябрь и октябрь 2026. Неподключённый месяц не превращается в нулевую зарплату: бот запросит подключение данных. Для следующего месяца добавьте отдельный `[[payroll_sources]]` с его ID файла, `month`, диапазонами и тем же форматом; прошлые источники сохраняйте. Один месяц нельзя подключить дважды. Подмена октября ноябрём в том же файле остановит проверку дат.

Проверка рабочего серверного доступа и чтение через плагин — разные проверки. Персональные данные и реальные зарплаты не включены в архив приложения или тестовые данные.

### Универсальный формат для готовых начислений

Адаптер поддерживает один или несколько листов/файлов с таблицей начислений. Названия столбцов настраиваются через `columns`. Необходимо сопоставить:

| Поле | Смысл |
|---|---|
| `record_id` | Уникальный ID начисления во всех источниках |
| `date` | Дата начисления: дата Google Sheets, `YYYY-MM-DD` или `ДД.ММ.ГГГГ` |
| `model_id` | Постоянный ID модели, не зависящий от смены псевдонима |
| `model_name` | Имя модели для проверки привязки |
| `amount_usd` | Уже рассчитанное начисление именно модели в USD; отрицательная корректировка допустима |

Пример находится в комментариях `studio.toml`. Этот альтернативный формат (`format = "rows"`) нельзя смешивать с `studio_daily_share`, чтобы не сложить одни начисления дважды. Существующую таблицу ради него менять не нужно.

В формате `rows` нет исходной выручки: администраторский отчёт полного оборота недоступен. Модельные отчёты и авансы используют готовые начисления этого формата. Бот сообщит об этом; восстановление оборота из начислений модели не выполняется. Используйте подключённый формат «Чеки».

## Размещение на Linux-сервере

Для контейнерного запуска нужен сервер с Docker Engine и Docker Compose **2.24+**, постоянным диском и исходящим HTTPS к Telegram и Google. Входящий порт, домен и сертификат приложению не нужны: оно получает команды через long polling. Запускайте **один экземпляр**, без горизонтального масштабирования. Короткий путь: `sh Server.sh setup`, отдельно разместить ключ, затем `sh Server.sh check` и `sh Server.sh start`. Ниже — те же действия вручную.

Проверка Compose поддерживает отсутствие `.env`: вместо ошибки о скрытом файле приложение объяснит, как задать `BOT_TOKEN` и пароль. `Server.sh start` до запуска проверяет наличие `.env`, ключа, локальные настройки и чтение Google. `check` и `run` останавливаются с понятной причиной при отсутствии/некорректности ключа, фотографий или прав записи в data. Содержимое секретов не выводится.

1. Распакуйте папку `studio-bot` на сервере и перейдите в неё. Проверьте комнаты и месячные источники в `studio.toml`.
2. Соберите образ:

```sh
docker build -t studio-bot:mvp .
```

3. Если переносите уже настроенную локальную копию, перенесите её `.env` отдельно. Для новой установки настройте единственный токен и пароль в локальном интерактивном окне сервера:

```sh
docker run --rm -it --user "$(id -u):$(id -g)" \
  --mount type=bind,src="$PWD",dst=/setup \
  -e STUDIO_ROOT=/setup studio-bot:mvp setup
```

Команда создаст или дополнит `.env`; пароль записывается туда как PBKDF2-хеш. Setup не заменяет уже настроенный пароль. Список Telegram ID можно оставить пустым. Одинарные кавычки вокруг хеша сохраняйте: они защищают символы `$` при чтении Docker Compose.

4. Создайте папку `secrets` и поместите туда ключ Google. Процесс контейнера работает с UID/GID `10001:10001`; ему нужен доступ на чтение ключа. На обычном Linux это можно настроить так:

```sh
sudo chown 10001:10001 secrets/google-service-account.json
sudo chmod 600 secrets/google-service-account.json
```

5. После настройки источника проверьте конфигурацию и запустите:

```sh
docker compose run --rm studio check
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 studio
```

6. Все открывают одного бота. Администратор вводит `/admin` → пароль; модели — `/start` и заполняют анкеты. Администратор подтверждает их и выбирает имена из таблицы для привязки. После выхода старые кнопки админки снова требуют пароль. Нажатие кнопки старого меню модели возвращает режим модели и закрывает админ-сессию.

`restart: unless-stopped` возвращает процесс после аварии и после перезагрузки сервера при работающем Docker. Healthcheck проверяет пульс процесса, а не доступность Google и Telegram; для уведомления владельца сервера о проблемах нужен мониторинг хостинга. Сам статус `unhealthy` не перезапускает контейнер автоматически.

Остановить: `docker compose stop`. Запустить снова: `docker compose up -d`. Обычный `docker compose down` сохраняет том данных. **Не используйте `down -v` для рабочей студии:** это удаляет историю, анкеты, расписание и заявки.

После изменения `.env` нужен `docker compose up -d --force-recreate`; простой restart не перечитывает переменные окружения. Для смены пароля остановите сервис, выполните команду из шага 3 с `password` вместо `setup`, затем пересоздайте контейнер.

### Резервная копия

Данные хранятся в отдельном томе `studio-data`, код и секреты в него не входят. Полностью остановите сервис перед резервным копированием. Например:

```sh
mkdir -p backups
docker compose stop
docker compose run --rm --user "$(id -u):$(id -g)" --entrypoint sh \
  -v "$PWD/backups:/backup" studio \
  -c 'tar -czf /backup/studio-data.tgz -C /app/data .'
docker compose up -d
```

Если пользователь хоста не может читать том, выполните только команду архивирования с `--user 0`. Копия содержит персональные и зарплатные сведения; храните её вместе с защищённой копией `.env`, `studio.toml` и ключа Google. Файл `studio-data.tgz` в примере перезаписывается, для истории копий задавайте разные имена. Восстановление делайте в остановленный пустой том и возвращайте владельца данных `10001:10001`.

## Проверка на Windows

Для чистой установки: Python **3.11 или новее**, затем **Verify.cmd → Install.cmd → Setup.cmd → ключ Google → Check.cmd → CheckGoogle.cmd → Start.cmd**. Python Launcher необязателен: установщик пробует `py -3`, `python`, `python3`. Можно явно указать интерпретатор через `STUDIO_PYTHON` или выполнить `python bootstrap.py install`. Зависимости закреплены по версиям; это не ограничивает Python одной минорной версией. Список проверенных версий — в VERIFICATION.md.

Install создаёт `data`, `secrets` и `.env` из `.env.example`, если его ещё нет. При повторной установке существующие настройки не заменяются. Рабочие `.env`, ключ и база в архив не входят; отдельно перенесите их при переезде. Не переносите `.venv` — установите зависимости заново. Пароль новой установки задаётся в Setup; для смены при остановленном приложении — **ChangePassword.cmd**. Ключ Google для Python: `data/google-service-account.json`. Другой путь можно задать через `GOOGLE_APPLICATION_CREDENTIALS` в `.env` или окружении; окружение имеет приоритет. Остановить локального бота — Ctrl+C в окне Start.cmd. Компьютер должен оставаться включённым.

Check проверяет локальные настройки, корректность JSON-ключа, фотографии и запись в data, без сетевых запросов. CheckGoogle отдельно проверяет реальное чтение таблиц; Telegram проверяется при старте. При переносе действующего приложения на сервер остановите Windows-копию до запуска серверной: один и тот же бот не должен опрашиваться двумя процессами.

Для Linux без Docker: `python3 bootstrap.py install`, `python3 bootstrap.py setup`, отдельно разместить ключ в data, затем `python3 bootstrap.py check`, `python3 bootstrap.py check-google`, `python3 bootstrap.py run`. Bootstrap автоматически использует `.venv` проекта. Минимальный Python 3.11 нужен в том числе для стандартного модуля `tomllib`; совместимость новых версий проверяется отдельно. Контейнер использует свой Python из Dockerfile; для проверки другого образа есть `--build-arg PYTHON_VERSION=3.14`.

### Повторная сборка архива

`python package_release.py` создаёт `Studio-Bot-MVP.zip` рядом с папкой проекта. Явный список файлов включает скрытые шаблоны и фотографии, но исключает ключи, `.env`, базу, историю, резервные копии и виртуальное окружение. В ZIP добавляется `MANIFEST.sha256`; `Verify.cmd` или `python3 bootstrap.py verify` проверяет распаковку. После ручного изменения исходников контрольные суммы старого выпуска будут отличаться — для нового выпуска пересоберите архив.

## Доступ и сохранность

Для Bothost с автоматической Python-сборкой главный файл — `main.py`. Платформа может выбирать `uv sync` при наличии `pyproject.toml`; зависимости в нём совпадают с закреплённым списком `requirements.txt`. После обновления зависимостей нужна пересборка, обычный перезапуск их не устанавливает. Рабочие ключ Google и SQLite хранятся отдельно в `/app/data`, токен и хеш пароля — в переменных окружения хостинга.

- Админ-доступ: пароль, сессия на 1 час; список Telegram ID опционален. После 5 неверных паролей пользователя — блокировка на 15 минут. Дополнительно после 25 ошибок со всех пользователей вход блокируется на 15 минут. Ограничения сохраняются при перезапуске; действующие сессии при этом не сохраняются.
- Пароль вводится после `/admin` в личном чате общего бота; бот пытается удалить это сообщение. Вход отменяет незавершённый ввод сообщения администратору, чтобы пароль не попал в обращение. Чат с ботом не является Secret Chat, поэтому используется отдельный пароль, отличный от паролей Telegram и Google.
- Получатели административных уведомлений сохраняются после успешного входа. После смены пароля они должны войти заново, чтобы продолжить получать новые уведомления; старые уже поставленные в очередь уведомления содержат только сообщение о наличии заявки.
- `.env`, папки `data`, `secrets`, личные ключи и базы не включаются в Git и Docker-образ. Логи библиотек не выводят токены, текст запросов и зарплатные сведения. Приложение само не шифрует SQLite и файлы секретов.
- В базе сохраняются анкеты, смены, заявки, обращения, снимки начислений для авансов и журнал действий администратора. Общий кеш зарплат находится в памяти.
- Уведомления доставляются через устойчивую очередь. При сбое сети возможна повторная доставка одного уведомления; заявки и их статусы от этого не дублируются. Заблокировавшему бота пользователю уведомление не доставить; ошибка видна администратору, сама заявка остаётся сохранённой.
- Незаконченный ввод анкеты, сообщения или суммы аванса не сохраняется после перезапуска. Уже подтверждённые записи сохраняются. Бот запрашивает ожидающие обновления Telegram, но не восстанавливает сообщения за пределами срока хранения Telegram.

## Приёмочная проверка после подключения

На двух тестовых Telegram-пользователях проверить: вход в админку без пароля отклоняется; после выхода старая кнопка не открывает зарплаты; анкету можно подтвердить без зарплатной привязки; два человека не занимают одну комнату; администратор видит смену и её длительность; записи следующей недели сохраняются без двойной брони; модель видит только свои суммы; изменение тестового начисления в таблице отражается по кнопке; аванс содержит оба периода; ответ администратора приходит модели; смена сохраняется после перезапуска контейнера.

Автоматические проверки: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest -q` и `python -m ruff check .`. Выполненные проверки и остающиеся ограничения описаны в `VERIFICATION.md`.
